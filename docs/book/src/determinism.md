# Determinism

The same input should give the same bits on every platform, so that a render on one machine
matches one on another. tpt-colour aims for that with four rules:

1. **Fixed operation order.** Sums and products are written in a set order, so the compiler cannot
   reassociate them. Matrix products are one helper, `mat3_mul`, with a fixed summation order.
2. **No fused multiply-add.** `a * b + c` is not contracted to a single FMA instruction, because
   that rounds differently from two operations.
3. **`libm` instead of platform maths.** Transcendental functions (`powf`, `cbrt`, `atan2`, and so
   on) come from `libm`, not from `std`, whose results vary by platform.
4. **Recorded bit patterns.** A test records the bit patterns of a set of outputs on x86-64, and
   CI runs the same test on ARM64 and builds for wasm32.

## What is checked

- The determinism test runs in the normal test suite on x86-64, and as a CI job on ARM64.
- The wasm32 target builds in CI. Its results are checked by the WebAssembly tests under Node.
- The golden-file gradient mesh test guards against regressions in the bulk path. Its reference
  is generated by this library, so it guards consistency, not correctness. The LittleCMS oracle
  covers correctness.

## Caveats

- The `simd` feature is an optional backend. It is bit-identical to the scalar path for the
  matrix/TRC batch, but this has only been run on x86-64 here.
- Bit patterns are a property of this code. A different compiler version can change instruction
  selection; the rules above are what keeps the results stable.
