# Changelog

All notable changes to `tpt-colour-icc` are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the crate uses
[Semantic Versioning](https://semver.org/). It is pre-1.0, so breaking changes can appear in minor
releases until 1.0.0.

The workspace-wide log is in the [root changelog](../../CHANGELOG.md).

## [Unreleased]

### Known limitations

- Perceptual device-side (B2A) output for sRGB into the official v4 LUT profile differs from
  LittleCMS by up to 12 codes at some colours. Relative intent matches within one code.
- The `mft1`/`mft2` 3×3 matrix is ignored. It only applies to XYZ-encoded PCS in B2A, which is rare.
- `multiProcessElements` (`mpet`) tables are not read. Intents that need them report `Unsupported`.
- Gamut mapping for LUT destination profiles is not done. Their own perceptual tables handle gamut
  compression.
- LUTs with more than eight input channels are `Unsupported`, not parsed.

### Added

- `IccProfile::to_bytes` writes matrix/TRC RGB and grey profiles (ICC v2.1, XYZ PCS). A written
  profile parses back and matches LittleCMS 2.19 on the three profiles checked.
- `check_profile_id`, `computed_profile_id` and `ProfileIdCheck`: the ICC profile ID (MD5, with three
  header fields zeroed), checked against real profiles.
- Grey (`GRAY`, `kTRC`) profiles, for matrix-free transforms to and from RGB.
- `ColourTransform::transform_u8` and `transform_u16`, for interleaved 8-bit and 16-bit RGB or RGBA
  buffers.
- `ColourTransform::transform_u8_image` and `transform_u16_image`. They take a row stride and leave
  padding untouched. New error `IccError::BufferLayout`.
- `ColourTransform::bake_clut`, which samples a transform onto a 3-D grid as a `Pipeline`. For
  Display P3 to sRGB, the mean error is 0.3 codes on a 33-point grid.
- `ColourTransform::to_cube`, which writes an Adobe `.cube` 3-D LUT. The CLI exposes it as
  `tpt-colour cube`.
- `ColourTransform::describe()` and `Step`: the transform's stage graph.
- `FromStr` for `RenderingIntent`, with `ParseIntentError`.
- A per-profile CLUT budget of 32 MiB of samples, which limits memory for hostile profiles.
- Optional `serde` feature, and a `simd` feature that uses `tpt-simd`. Both are off by default.
- LittleCMS fixtures for the device-side (B2A) direction, generated by
  `tools/oracle/generate_b2a_fixtures.py`.

### Changed (behaviour)

- CLUTs with more than eight inputs are `Unsupported`, not parsed. Multilinear lookup touches 2^n
  corners per pixel, so the cap bounds work per pixel. Malformed tables stay `BadTag`.

### Fixed

- `with_white_patched` could panic when a curve output left `[0, 1]`. CLUT inputs are now clamped
  in `Pipeline::eval`, as LittleCMS does.
- Absolute colorimetric intent scales by the source and destination media white points (`wtpt`).
  It previously equalled relative colorimetric.
- Perceptual transforms to v4 destinations skip black point compensation when the two black points
  are equal, which keeps the fast paths.
- A bad or unused LUT tag, or an unreadable `wtpt` or `chad`, no longer fails the whole profile.
  The affected intent reports `Unsupported`.
- A `para` curve of function type 0 (`x^g`) is read as `Trc::Gamma`, not `Trc::Parametric`, so its
  inverse is analytic.
- Pure power curves are kept analytic when baked. The table inverse was about 1.6 codes out near
  black for γ = 2.2.
- Sampled curves with dips are levelled to a running maximum, so their inverse is monotonic.
- NaN inputs no longer leak through pipelines or the matrix inverse.
- The ICC description is read from the `desc` tag only. The previous lookups for `mluc` and `text`
  could never match a tag name.

### Performance

- Gamma-only profiles evaluate their power curves directly, not through a table. That is slower per
  pixel, but exact.
