# tpt-colour-capi

A C ABI for [tpt-colour](https://github.com/tpt-solutions/tpt-colour), with a header generated by
`cbindgen`. Use it from C, C++, or any language that can call C functions through FFI.

This crate is not part of the default workspace, and it is not published. The workspace forbids
`unsafe`, and the C ABI needs it, so the crate builds on its own.

## Build

```sh
cd crates/tpt-colour-capi
cargo build --release
```

This produces `tpt_colour.dll`, `libtpt_colour.so` or `libtpt_colour.dylib` in `target/release`,
along with a static library. The header is `include/tpt_colour.h`.

## Usage

```c
#include "tpt_colour.h"
#include <stdint.h>
#include <stdio.h>

int main(void) {
    uint8_t rgba[4];
    int32_t status = tpt_parse_colour("rebeccapurple", 13, rgba);
    if (status != 0) {
        return 1;
    }
    printf("%u %u %u %u\n", rgba[0], rgba[1], rgba[2], rgba[3]);
    return 0;
}
```

## Conventions

- Every function that can fail returns `0` on success, and a negative status code otherwise. The
  codes are listed in the header.
- Colours are arrays of `float` in `[0, 1]`, and 8-bit colours are arrays of `uint8_t`.
- Strings are UTF-8 with an explicit length, so they need no terminating NUL.
- The caller owns every pointer. Each function documents what it reads and writes.
- `tpt_manager_new` is the only allocation. Release it with `tpt_manager_free`.
- A manager is used by one thread at a time.

## Regenerate the header

After changing the C API, regenerate the header:

```sh
cd crates/tpt-colour-capi
cbindgen --config cbindgen.toml --crate tpt-colour-capi --output include/tpt_colour.h
```

## Tests

The Python `unittest` suite calls the built library through `ctypes`, using the signatures in the
header. Build the library first:

```sh
cargo build --release
python -m unittest discover -s tests -v
```

The full binding guide is in [`docs/book/src/bindings.md`](../../docs/book/src/bindings.md).
